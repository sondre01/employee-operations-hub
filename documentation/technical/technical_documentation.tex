\section{System Architecture \& Deployment Topology}
% ==========================================

The Employee Operations Hub is architected for dual-target execution:
\begin{enumerate}
    \item \textbf{Production Cloud Architecture (Vercel + Supabase)}:
    \begin{itemize}
        \item \textbf{Frontend Clients}: Two decoupled single-page applications (\texttt{apps/employee-portal} and \texttt{apps/ticketing-desk}) bundled via Vite and served from edge CDN nodes.
        \item \textbf{Serverless API Layer}: ES-module serverless endpoints (\texttt{api/\_handler.js}) running on Vercel Node.js runtime with connection-pooled PostgreSQL queries.
        \item \textbf{Data Persistence}: Supabase Managed PostgreSQL with automatic failover and isolated schema namespace (\texttt{employee\_hub}).
    \end{itemize}
    \item \textbf{Containerized / Local Architecture (Docker + ASP.NET Core 8)}:
    \begin{itemize}
        \item Multi-stage containerized backend with ASP.NET Core 8 Web API, Entity Framework Core 8, and Swagger OpenAPI specification.
    \end{itemize}
\end{enumerate}

\subsection{Key Data Integrity Rules}
\begin{itemize}
    \item \textbf{WorkEmail Uniqueness}: Enforced via unique B-tree index on \texttt{LOWER(WorkEmail)}.
    \item \textbf{Safe Integer Coercion}: All integer parameters in API handlers pass through \texttt{safeInt(val)} to eliminate PostgreSQL \texttt{22P02} NaN errors.
    \item \textbf{Connection Fallback}: Database pooler automatically detects partial hostname string truncation (e.g. from copy-paste line breaks) and falls back to verified direct poolers.
\end{itemize}

\section{Security Architecture \& RBAC}
% ==========================================

\subsection{Role-Based Access Levels}
The system enforces four distinct operational roles:
\begin{enumerate}
    \item \textbf{SuperAdmin (Role 1)}: Absolute read/write access across all queues, audit trails, and access management. Automatically assigned to primary system administrator.
    \item \textbf{Admin (Role 2)}: Departmental lead privileges, allowing ticket re-assignment, priority escalation, and queue management.
    \item \textbf{Agent (Role 3)}: Operational specialists in IT, HR, or Finance with resolution capabilities on assigned tickets.
    \item \textbf{Employee (Role 0)}: Base workforce tier. Restricted to personal profile, attendance logging, submitted tickets, and assigned hardware.
\end{enumerate}

\subsection{Credential Storage Security}
Passwords are protected using PBKDF2 with SHA-256:
\begin{itemize}
    \item \textbf{Salt}: 16 cryptographically secure random bytes generated per user.
    \item \textbf{Iterations}: 10,000 computation cycles.
    \item \textbf{Encoding}: \texttt{\{iterations\}:\{saltHex\}:\{hashHex\}}.
\end{itemize}

\section{Cloud Deployment \& Environment Configuration}
% ==========================================

\begin{lstlisting}[language=bash,caption={Required Production Environment Variables}]
# Supabase PostgreSQL Connection Pool URL
SUPABASE_DB_URL=postgresql://postgres.xxx:[PASSWORD]@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres?sslmode=require

# Fallback Database URL
DATABASE_URL=postgresql://postgres.xxx:[PASSWORD]@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres?sslmode=require

# Application Interconnect URLs
VITE_TICKETING_URL=https://your-ticketing-desk.vercel.app
VITE_PORTAL_URL=https://your-employee-portal.vercel.app
\end{lstlisting}

\begin{tipbox}[Zero-Config Client Base URL]
The frontend API client automatically defaults to relative \texttt{'/api'} on production domains, ensuring zero CORS preflight latency and complete immunity from misconfigured environment variables.
\end{tipbox}
