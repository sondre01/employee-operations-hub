\subsection{Dual Database Provider Strategy}
The API implements dynamic provider switching in \texttt{Program.cs} based on configuration:
\begin{itemize}
    \item \textbf{SQLite (Default Local)}: Activated when \texttt{DatabaseProvider} is omitted or set to \texttt{"Sqlite"}. It stores data in \texttt{employee\_hub.db} and uses \texttt{EnsureCreatedAsync()} to guarantee frictionless developer onboarding with zero pre-installed database engines.
    \item \textbf{PostgreSQL (Container / Production)}: Activated when \texttt{DatabaseProvider="PostgreSql"}. It connects via Npgsql and automatically applies pending schema migrations via \texttt{MigrateAsync()}.
\end{itemize}

\section{Role-Based Access Control (RBAC) Architecture}

\subsection{Dual-Dimension Conceptual Model}
The frontend interface is split into two distinct operational dimensions via the unified header bar:

\begin{enumerate}
    \item \textbf{Dimension 1: Employee Portal (Accessible to ALL)}:
    Designed for every employee (internal core staff and dedicated external client developers). Features include:
    \begin{itemize}
        \item \textbf{Single-Frame Multi-Box Profile Architecture}: High-density, non-scrollable dashboard organized into two balanced tiers:
        \begin{enumerate}[label=\alph*.]
            \item \textit{Primary Top Row (3 Box Containers, Equal Height)}:
            \begin{itemize}
                \item \textbf{Left Box}: \textit{Employment Information \& Classification} -- Name breakdown (Last Name, First Name, Middle Name), Job Role, Client Engagement, Department, Lead, and Hardware Custody indicators.
                \item \textbf{Middle Box (Wider)}: \textit{Workday Time Clock \& Shift Station} -- Longer width containing live status, dual cross-border Manila/Copenhagen digital clocks, visual shift progress meter, and 5-action punch buttons (Clock In, Break, Lunch Out, Lunch In, Clock Out).
                \item \textbf{Right Box}: \textit{Company Announcements \& HR Bulletins} -- Vertical bulletin cards from HR People Operations.
            \end{itemize}
            \item \textit{Operational Bottom Row (3 Minimal Boxes)}:
            \begin{itemize}
                \item \textbf{Left Minimal Box}: \textit{Onboarding Requirements Fulfillment} -- Radial SVG completion meter (75\% verified) and statutory clearance status.
                \item \textbf{Middle Minimal Box (Wider)}: \textit{Pending Requests \& Adjustments Summary} -- Concise KPI numbers summary (Time Corrections, Overtime Pre-Approvals, Shift Adjustments) and manager routing.
                \item \textbf{Right Minimal Box}: \textit{Payroll Schedule \& Cycle Cut-Offs} -- Dynamic single-cycle card displaying Pay Period Date, Filing Cut-Off, Approval Cut-Off, and Crediting Date.
            \end{itemize}
        \end{enumerate}
        \item \textbf{Dedicated Attendance Tab (\texttt{AttendanceView.jsx})}: Full workday biometric history ledger, break/lunch tracking, and monthly timecard metrics.
        \item \textbf{Dedicated Requests Tab (\texttt{TimeRequestsView.jsx})}: Self-service filing portal for time corrections, overtime pre-approvals, and shift adjustments directed to designated managers.
        \item \textbf{Calendar \& Compliance}: Dual Philippine-Danish holiday calendar and company compliance policy acknowledgements.
    \end{itemize}
    \item \textbf{Dimension 2: Ticketing System Management (Operational Staff Only)}:
    Strictly isolated and visible \textit{only} to internal employees who have been granted operational desk access (\texttt{HasTicketingAccess = true}). Features a streamlined, 1-word minimalist navigation bar:
    \begin{itemize}
        \item \textbf{Queue}: Triage and manage incoming IT Infrastructure and HR/Legal service requests.
        \item \textbf{Analytics}: Real-time SLA compliance charts, queue velocity, and priority distribution.
        \item \textbf{Departments}: Departmental routing configuration and operational unit settings (Admin).
        \item \textbf{Access}: Operational desk RBAC permission delegation and manager elevation (Staff).
        \item \textbf{Roster}: Dedicated outstaffing roster and client-developer assignment management.
    \end{itemize}
\end{enumerate}

\subsection{Granular Authorization Flags}
Each employee entity tracks operational capabilities using boolean flags:
\begin{itemize}
    \item \texttt{IsInternal}: Distinguishes internal operations staff from client-dedicated offshore software engineers.
    \item \texttt{HasTicketingAccess}: Controls visibility and entry to Dimension 2 (Ticketing Management).
    \item \texttt{CanAssignEmployees}: Authorizes privileged personnel (Super Admin or DevOps Admin) to grant or revoke ticketing access and delegate operational queues.
\end{itemize}

\section{Domain Entities \& Data Models}

\subsection{Core Entity Definitions}

\subsubsection{Employee Entity (\texttt{Employee.cs})}
Represents both internal core team members and external client-dedicated engineers.
\begin{itemize}
    \item \texttt{Id} (int, PK): Unique identifier.
    \item \texttt{FirstName}, \texttt{MiddleName}, \texttt{LastName}, \texttt{FullName} (string), \texttt{WorkEmail} (string, Unique): Identity credentials broken down into discrete name components with combined full name resolution.
    \item \texttt{PasswordHash} (string): PBKDF2/SHA256 salted password hash.
    \item \texttt{JobTitle} (string): Professional role (e.g. Operations Specialist, Account Manager, Developer).
    \item \texttt{PrimaryTechStack} (string, Optional): Professional competencies (omitted from initial sign up credentials to accommodate non-technical staff).
    \item \texttt{EmploymentType} (Enum): \texttt{InternalCore (1)} or \texttt{ClientDedicated (2)}.
    \item \texttt{Role} (Enum): \texttt{AdminHr (1)}, \texttt{DanishClientLead (2)}, or \texttt{Developer (3)}.
    \item \texttt{TicketingRole} (Enum): \texttt{None (0)}, \texttt{SuperAdmin (1)}, \texttt{DevOpsAdmin (2)}, \texttt{DepartmentManager (3)}, or \texttt{DepartmentMember (4)}.
    \item \texttt{IsInternal}, \texttt{HasTicketingAccess}, \texttt{CanAssignEmployees} (bool): Security flags.
    \item \texttt{ClientName} (string?): Client identifier if dedicated (e.g., \textit{"Nordic Logistics ApS"}).
    \item \texttt{DepartmentId} (int?, FK): Associated operational department.
\end{itemize}

\subsubsection{Department Entity (\texttt{Department.cs})}
Represents operational units that service internal tickets and manage infrastructure.
\begin{itemize}
    \item \texttt{Id} (int, PK), \texttt{Name} (string), \texttt{Description} (string), \texttt{CreatedAtUtc} (datetime).
    \item Pre-seeded departments: \textit{Dev Operation}, \textit{IT Team}, \textit{HR/Recruitment}, \textit{Finance}.
\end{itemize}

\subsubsection{Ticket Entity (\texttt{Ticket.cs})}
Tracks operational service requests across the enterprise lifecycle.
\begin{itemize}
    \item \texttt{Id} (int, PK), \texttt{Title} (string), \texttt{Description} (string), \texttt{Priority} (string).
    \item \texttt{Queue} (Enum): \texttt{ItInfrastructure (1)} or \texttt{HrLegal (2)}.
    \item \texttt{Status} (Enum): \texttt{Open (1)}, \texttt{InProgress (2)}, \texttt{Resolved (3)}.
    \item \texttt{CreatedByEmployeeId} (int, FK), \texttt{AssignedToEmployeeId} (int?, FK).
    \item \texttt{ResolutionNotes} (string?), \texttt{CreatedAtUtc}, \texttt{UpdatedAtUtc}.
\end{itemize}

\subsubsection{Hardware Custody Item (\texttt{HardwareCustodyItem.cs})}
Tracks company equipment issued to developers.
\begin{itemize}
    \item \texttt{Id} (int, PK), \texttt{EmployeeId} (int, FK).
    \item \texttt{ModelName} (string, e.g., \textit{"MacBook Pro 16-inch M3 Max"}).
    \item \texttt{SerialNumber} (string), \texttt{AssetTag} (string).
    \item \texttt{AssignedDate} (DateOnly), \texttt{ReturnDate} (DateOnly?).
    \item \texttt{Status} (string): \texttt{"Active"}, \texttt{"InRepair"}, or \texttt{"Returned"}.
    \item \texttt{Notes} (string?): Condition reports, peripheral bundles.
\end{itemize}

\subsubsection{Cross-Border Holiday (\texttt{Holiday.cs})}
Powers the dual operations calendar to bridge international schedule gaps.
\begin{itemize}
    \item \texttt{Id} (int, PK), \texttt{Title} (string), \texttt{HolidayDate} (DateOnly).
    \item \texttt{Country} (Enum): \texttt{Philippines (1)} or \texttt{Denmark (2)}.
    \item \texttt{IsWorkingDay} (bool): Accommodates special working holidays and local observances.
\end{itemize}

\subsubsection{Policy \& Compliance (\texttt{PolicyDocument.cs} \& \texttt{PolicyAcknowledgement.cs})}
Maintains audit logs of legal and regulatory compliance.
\begin{itemize}
    \item \texttt{PolicyDocument}: \texttt{Title}, \texttt{Version}, \texttt{SummaryMarkdown}, \texttt{IsMandatory}, \texttt{PublishedAtUtc}.
    \item \texttt{PolicyAcknowledgement}: Tracks employee ID, policy ID, and digital signature timestamp.
\end{itemize}

\section{Deployment \& Execution Guide}

\subsection{Fastest Command to Run the Backend}

The backend API can be launched with a single command from the project root:

\begin{lstlisting}[language=bash]
# Option A: Via npm script defined in package.json
npm run start:backend

# Option B: Direct .NET 8 CLI execution
dotnet run --project backend/src/EmployeeHub.Api --launch-profile http
\end{lstlisting}

\begin{tipbox}[Zero-Config SQLite Initialization]
When launched using the \texttt{http} profile, the API binds to \textbf{\url{http://localhost:5000}} and immediately provisions the local SQLite database (\texttt{employee\_hub.db}) complete with pre-seeded personas, departments, policies, and tickets. No database installation is required.
\end{tipbox}

\subsection{Running the Complete Stack Locally}

To run both backend and frontend concurrently for local development:

\begin{enumerate}
    \item \textbf{Start the Backend API}:
    \begin{lstlisting}[language=bash]
    npm run start:backend
    \end{lstlisting}
    API is live at \url{http://localhost:5000}; Swagger UI at \url{http://localhost:5000/swagger}.

    \item \textbf{Start the React Frontend}:
    In a separate terminal window:
    \begin{lstlisting}[language=bash]
    npm --prefix frontend run dev
    \end{lstlisting}
    The Vite dev server will launch at \textbf{\url{http://localhost:5173}}.
\end{enumerate}

\subsection{Full-Stack Production Deployment with Docker Compose}

For staging or production deployments running PostgreSQL 16:

\begin{lstlisting}[language=bash]
docker compose up --build
\end{lstlisting}

\section{Cross-Border Operational Workflows}

\subsection{Danish-Philippine Operational Alignment}
The system specifically addresses the logistical challenges of offshore software teams dedicated to Danish client operations:

\begin{itemize}
    \item \textbf{Dual Operations Calendar}:
    Displays simultaneous Philippine and Danish public holidays side-by-side. Highlights \textit{Special Working Holidays} and non-overlapping days where coverage planning is critical (e.g., Danish \textit{Store Bededag} or Philippine \textit{Araw ng Kagitingan}).
    \item \textbf{Hardware Custody Receipts}:
    Maintains transparent custody records of premium corporate hardware issued to offshore developers (asset serial tags, MacBook model numbers, delivery dates, and return condition logs).
    \item \textbf{Statutory Remittance \& HR Requests}:
    Dedicated routing for Philippine legal compliance tickets (Certificate of Employment requests, SSS, PhilHealth, Pag-IBIG inquiries, and tax form 2316 processing).
    \item \textbf{Client Dedicated Isolation}:
    Engineers dedicated to Danish clients are restricted from viewing other client teams or internal departmental ticketing queues, ensuring strict client confidentiality.
\end{itemize}
